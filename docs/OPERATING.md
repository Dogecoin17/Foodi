# Foodi – Operating Guide

Complete instructions for running the Foodi video prototype, from a fresh
checkout to the recorded demo. Everything here runs on one laptop (the CCM);
no Arduino hardware is required except where explicitly marked optional.

Branches: **`video-prototype`** = what you demo and film. `main` = the
hardware-faithful product code (BLE feeder firmware, UNO Q MCU bridge).

---

## 0. One-time setup

Requirements: Python 3.12+, git. PlatformIO is only needed for the optional
firmware build (section 6).

```bash
git clone https://github.com/Dogecoin17/Foodi.git
cd Foodi
git checkout video-prototype

cd ccm
python -m venv .venv
.venv\Scripts\activate          # Windows (Git Bash: source .venv/Scripts/activate)
pip install -r requirements.txt
pip install python-pptx         # only needed to regenerate the presentation
```

The YOLOX model (`ai/yolox_nano.onnx`) is in the repo; nothing else to download.

## 1. Run the core demo (simulated feeder, pre-recorded video)

```bash
cd ccm
.venv\Scripts\activate
python -m app.seed_demo --force     # 30 days of history incl. a 2-day intake drop
python -m uvicorn app.main:app
```

Open **http://localhost:8000**. You should see:

- **Feeder card** – bowl weight, hopper %, state, case temperature (– when no MCU)
- **Feed now** – dispenses 30 g on the simulated feeder; watch the event appear
- **Schedule** – add/remove meals; they fire on the wall clock
- **Live view** – the pre-recorded clip of a cat with the AI detection overlay
- **Daily consumption** – 30-day bar chart, anomalous days in red
- **Insights** – "Today's amount is about 45% below the recent average…"
- **Feeding history / Alerts**

Stop with Ctrl+C. The database is `ccm/foodi.db`; re-run the seed command to reset.

## 2. Live phone camera (the shoot setup)

The phone is the feeder camera, streaming to the laptop over Wi-Fi – the same
role the ESP32-S3 camera has in the final product.

1. Both phone and laptop on the **same Wi-Fi** (a phone hotspot works and is
   venue-proof; enable it on a *second* phone or a travel router).
2. Install an IP webcam app on the camera phone:
   - Android: **IP Webcam** → scroll down → *Start server*
   - iPhone: **EpocCam** or **Camo**
3. Note the URL shown on the phone screen, e.g. `http://192.168.1.50:8080/video`.
4. Mount the phone above/in front of the bowl. **Fix its position** (tape the
   stand); the scale region in section 3 depends on it.
5. Start the backend:

```bash
FOODI_VIDEO_URL=http://<phone-ip>:8080/video python -m uvicorn app.main:app
```

The dashboard's Live view now shows the phone stream with the overlay:
green box + confidence on the pet, red box + **EATING** banner when the pet is
at the bowl and the weight is falling. If the phone drops, the backend
reconnects automatically.

Rehearse without a phone: `FOODI_VIDEO_URL=../ai/clips/cica1.mp4`

## 3. Reading the kitchen scale through the camera

The backend decodes the scale's 7-segment LCD from the video – no wiring.

1. Put the bowl on the scale, display facing the camera, roughly frontal.
   Avoid lamp glare on the display (tilt the scale or the light).
2. Grab a still frame: open `http://<phone-ip>:8080/photo.jpg` in a browser
   and save it.
3. Open the image in Paint/Photos and note the pixel coordinates of the
   display's **top-left** and **bottom-right** corners (hover the mouse).
4. Start the backend with the region:

```bash
FOODI_VIDEO_URL=http://<phone-ip>:8080/video FOODI_SCALE_ROI=x1,y1,x2,y2 python -m uvicorn app.main:app
```

Verify: the overlay draws a yellow box around the display with the decoded
grams, and the dashboard bowl weight follows the real scale. Put an object on
the scale and watch the number change. Readings are median-filtered; when the
pet blocks the display the last value is held on purpose.

If the decode is wrong or unstable: re-check the ROI is tight around the
digits, reduce glare, and keep the camera still. Send a frame to the team to
re-tune thresholds.

## 4. UNO Q feasibility measurement (for the judges)

Runs the whole stack pinned to 1 CPU core – a conservative stand-in for the
UNO Q's 4× Cortex-A53 – and writes `docs/performance.md`:

```bash
cd ccm
python simulate_uno_q.py --cores 1 --duration 60 --video-url ../ai/clips/cica1.mp4
# or against the real camera: --video-url http://<phone-ip>:8080/video
```

Reference result: 190 MB RAM, 25% of one core, 12 detections/s (need 1–2).
Re-run after any setup change so the report matches what you show.

## 6. Feeder prototype: ESP-WROOM-32 + 28BYJ-48 stepper

The prototype feeder uses an ESP-WROOM-32 devkit. It speaks the same BLE
protocol as the final product, so the laptop CCM treats it like real hardware.
There is no load cell: the stepper doses volumetrically (steps per gram) and
the CCM reads the actual bowl weight from the kitchen scale via the camera
(section 3).

### Wiring (28BYJ-48 + ULN2003)

| ULN2003 | ESP32 GPIO | Note |
|---|---|---|
| IN1 | 25 | |
| IN2 | 26 | |
| IN3 | 27 | |
| IN4 | 14 | |
| + | 5V (VIN) | ULN2003 powers the motor, not a GPIO |
| – | GND | common ground |

Do NOT use GPIO 6-11 on the WROOM-32 (connected to the internal flash).
Avoid 0/2/12/15 (boot strapping pins).

### Build and flash

```bash
cd feeder
.venv/bin/pio run -e esp32dev                    # build
.venv/bin/pio run -e esp32dev -t upload          # flash (hold BOOT if asked)
.venv/bin/pio device monitor -b 115200           # serial console: "foodi-feeder up, advertising"
```

Serial console commands: `status`, `refill`, `tare`.

### Run the CCM against the real feeder

```bash
cd ccm
FOODI_FEEDER=ble FOODI_VIDEO_URL=http://<phone-ip>:8080/video FOODI_SCALE_ROI=x1,y1,x2,y2 \
  python -m uvicorn app.main:app
```

No MAC address needed: the backend scans for the BLE name `foodi-feeder`.
Press **Feed now** – the stepper turns and the scale's number climbs on the
dashboard. If BLE is flaky, the feeder keeps its schedule autonomously and
reconnects with backoff.

### Calibrate the stepper

Dispense 50 g via Feed now, weigh what actually came out, and update
`STEPS_PER_GRAM` in `feeder/src/main.cpp`:
`new_value = 41.0 * 50 / measured_grams`, then rebuild and reflash.

## 8. Optional: UNO Q deployment (when the board arrives)

1. Connect the UNO Q via USB-C, open **Arduino App Lab**, first-time setup:
   Linux password + Wi-Fi credentials.
2. Copy the repo to the board, `pip install -r ccm/requirements.txt`, run the
   backend with `--host 0.0.0.0`. Dashboard: `http://<uno-q-ip>:8000`.
3. Flash `ccm/mcu/foodi_ccm_mcu/foodi_ccm_mcu.ino` to the STM32 via App Lab
   (fan control + status LEDs), then run the backend with `FOODI_MCU=bridge`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Dashboard shows clip, not live video | `FOODI_VIDEO_URL` unset or phone unreachable; check the URL in a browser first |
| Live view card missing entirely | no video source at all; set `FOODI_VIDEO_URL` or restore `ai/results/cica1_roi.mp4` |
| Scale reads `--` or wrong digits | ROI off (re-do section 3), glare, or camera moved |
| High CPU fans spinning | normal during live AI; stop leftover servers (see below) |
| Port already in use | another uvicorn is running: PowerShell `Get-Process python` → `Stop-Process -Id <pid>` |
| Leftover python eating CPU | same as above; the simulator kills its own children, Ctrl+C handles the rest |
| Phone stream stutters | move phone/laptop closer to the hotspot; the pipeline reconnects on its own |

## Environment variable reference

| Variable | Default | Purpose |
|---|---|---|
| `FOODI_VIDEO_URL` | – | live source: phone MJPEG URL, camera index, or video file |
| `FOODI_SCALE_ROI` | – | scale display region `x1,y1,x2,y2` in frame pixels |
| `FOODI_VIDEO_MODEL` | `ai/yolox_nano.onnx` | detection model path |
| `FOODI_VIDEO_THREADS` | 0 (all cores) | inference thread cap |
| `FOODI_VIDEO` | `ai/results/cica1_roi.mp4` | fallback clip |
| `FOODI_FEEDER` | `fake` | `fake` (simulator) or `ble` (real feeder) |
| `FOODI_BLE_ADDRESS` | – | feeder MAC when `FOODI_FEEDER=ble` |
| `FOODI_MCU` | `off` | `bridge` on the UNO Q (fans/LEDs) |
| `FOODI_DB` | `foodi.db` | SQLite path |
| `FOODI_MAX_PORTION_G` / `FOODI_DAILY_MAX_G` | 200 / 600 | safety clamps |

## Shoot-day checklist

1. `python -m app.seed_demo --force`
2. Phone mounted, streaming, laptop on the same Wi-Fi
3. Scale positioned, ROI measured (section 3)
4. `FOODI_VIDEO_URL=... FOODI_SCALE_ROI=... python -m uvicorn app.main:app`
5. Browser open at http://localhost:8000, Live view showing the overlay
6. Follow `docs/demo-script.md`
